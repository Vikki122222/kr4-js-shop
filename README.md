## О проекте

Контрольная работа №4 выполнена в отдельном репозитории `kr4-js-shop` на основе адаптивного HTML/CSS-интернет-магазина AEGIS COSPLAY из контрольной работы №3 (`kr3-responsive-shop`). Основа магазина была создана ранее в КР №1.

В КР №4 к готовым страницам добавлены JavaScript-интерактивность, массив товаров, динамическая генерация карточек, поиск, фильтрация, сортировка, корзина и клиентская проверка формы заказа.

Используются **HTML, CSS и чистый JavaScript**. Вёрстка основана на CSS Grid, Flexbox и медиазапросах. Bootstrap, React и Vue в этом проекте не применяются.

**Проект учебный:** реальные заказы и сообщения на сервер не отправляются. Результат заполнения формы является локальной демонстрацией проверки данных. Корзина работает в браузере и сохраняет состояние через `localStorage`.

## Страницы сайта

- `index.html` — главная страница: презентация магазина, преимущества, популярные костюмы, декоративная CSS-анимация и учебный блок проверки JavaScript.
- `catalog.html` — интерактивный каталог с карточками, поиском, фильтром по категории, сортировкой, счётчиком результатов и добавлением товара в корзину.
- `product.html` — подробная страница костюма Афины с изображениями и таблицей характеристик.
- `cart.html` — корзина: выбранные товары, количество, стоимость, удаление и пустое состояние.
- `order.html` — оформление учебной заявки, проверка обязательных полей и сообщения об ошибках.
- `contacts.html` — сведения о магазине и форма обратной связи без отправки данных на сервер.

## Каталог товаров и данные

Массив `products` в `js/data.js` содержит **8 товаров** единой структуры. У каждого есть поля:

- `id` — уникальный идентификатор;
- `title` — название;
- `category` — категория;
- `price` — цена числом;
- `discountPercent` — процент скидки;
- `rating` — рейтинг либо `null`;
- `isAvailable` — наличие товара;
- `image` — путь к изображению либо пустая строка;
- `description` — текстовое описание.

Первые шесть костюмов перенесены из КР №3. Для выполнения требования о 8–12 товарах добавлены две учебные позиции: **«Костюм Артемиды»** и **«Звёздная чародейка»**. Для товаров без фотографий используются текстовые заглушки, а не выдуманные изображения.

Категории (`mythology`, `magic`, `fantasy`) совпадают со значениями элементов фильтра на странице каталога.

## Интерактивность: DOM и события

Карточки каталога не прописаны вручную по одной в HTML. Скрипт находит контейнер через `querySelector()`, создаёт элементы с помощью `document.createElement()`, присваивает классы через `classList`, заполняет текст с помощью `textContent` и добавляет карточки в документ через `append()`.

Состояние каталога (`catalogState`) содержит поисковую строку, категорию и тип сортировки. При изменении поля поиска или выпадающих списков обработчики `addEventListener('input', ...)` и `addEventListener('change', ...)` запускают повторную подготовку данных и перерисовку карточек.

Реализованы:

1. **Поиск по названию** — без учёта регистра, с удалением пробелов по краям строки.
2. **Фильтрация по категории** — конкретная категория либо все товары.
3. **Сортировка** — исходный порядок, по возрастанию и убыванию цены, по названию.
4. **Счётчик** — показывает, сколько товаров соответствует условиям.
5. **Пустое состояние** — выводит сообщение, если совпадений нет.
6. **Кнопки товаров** — используют `data-product-id`, а обработчик клика делегирован контейнеру.

Для сортировки используется **копия массива**, чтобы не менять исходный порядок `products`.

## Корзина — самостоятельная доработка

В рамках итоговой КР №4 реализована отдельная страница `cart.html` и файл `js/cart.js`.

- Доступный товар можно добавить из каталога.
- В навигации показан счётчик количества товаров в корзине.
- Для каждой позиции отображаются название, количество и стоимость.
- Повторное добавление одного товара увеличивает его количество.
- Общая сумма рассчитывается методом `reduce()`.
- Кнопка «Удалить» убирает выбранную позицию.
- После удаления всех позиций выводится сообщение «Корзина пуста».
- Содержимое корзины сохраняется в `localStorage` под ключом `kr4-js-shop-cart`.
- При чтении сохранённых данных проверяются их формат и идентификаторы товаров.

В `localStorage` сохраняются **только идентификатор товара и количество**. Данные формы заказа туда не записываются.

## Форма заказа и валидация

На странице `order.html` используется обработчик события `submit` с `event.preventDefault()`: обычная отправка на сервер отменяется.

Проверяются:

- имя (не менее двух символов);
- корректность формата e-mail;
- телефон (11 цифр, начало с `7` или `8`);
- выбранный размер костюма;
- согласие на обработку персональных данных.

Ошибки отображаются возле соответствующих полей через `textContent`. При неправильном вводе выставляются атрибуты `aria-invalid` и `aria-describedby`. При исправлении ошибок сообщение очищается.

После корректного заполнения показывается текст: **«Форма прошла учебную проверку. Данные не отправлены.»** Форма очищается. Реальной оплаты или отправки заявки нет.

## Безопасный вывод данных

Для текстовых значений, полученных из пользовательского ввода, форм, `localStorage` и потенциальных внешних источников, применяется `textContent`, а не `innerHTML`.

`textContent` записывает строку как текст, не выполняя находящуюся в ней HTML-разметку. Для создания элементов применяется `createElement()`, для изменения классов — `classList`, для событий — `addEventListener()`.

Это снижает риск выполнения нежелательной разметки или скриптов при выводе непроверенных данных.

### Дополнительное оформление AEGIS COSPLAY

В проекте сохранены тёмно-фиолетовая палитра, полупрозрачные панели, мягкие границы, скругления и эффекты наведения. Переменные и базовые стили находятся в `style.css`, адаптивность и декоративные эффекты — в `responsive.css`.

На главной странице есть **12 декоративных конфет**, созданных HTML и CSS без JavaScript. Их движение задаётся анимацией `@keyframes candyFloat`; элементы не перехватывают нажатия благодаря `pointer-events: none`. На небольших экранах декор скрывается, а при `prefers-reduced-motion: reduce` анимация отключается.

![Схема декоративных конфет на главной странице](images/candy-layout.png)

*Это схема расположения декоративных элементов, а не снимок работающего сайта.*

На странице `contacts.html` сохранена учебная форма обратной связи с темой, сообщением и согласием. Данные этой формы также не отправляются на сервер.

## Как запустить проект

### Через WebStorm

1. Открыть папку `kr4-js-shop` в WebStorm.
2. Запустить `index.html` через локальный сервер WebStorm.
3. Перейти на страницы через меню сайта.

### Через Python (альтернативный способ)

В терминале в корне проекта выполнить:

```bash
python -m http.server 8000
```

Открыть в браузере: http://localhost:8000/index.html

Для проверки JavaScript использовать **DevTools → Console**, для пошаговой отладки — **DevTools → Sources → Breakpoints**.

## Как проверить КР №4

1. Открыть `catalog.html`. Убедиться, что отображаются **8 товаров**.
2. Ввести часть названия костюма — проверить изменение результата без перезагрузки.
3. Выбрать категорию и сортировку по цене — проверить состав и порядок карточек.
4. Ввести заведомо несуществующее название — увидеть сообщение о пустом результате и счётчик `0`.
5. Добавить доступный товар в корзину. Проверить обновление счётчика в навигации.
6. Открыть `cart.html` — проверить название товара, количество и общую сумму.
7. Обновить страницу — убедиться, что корзина восстановилась из `localStorage`.
8. Удалить товар — проверить пустое состояние корзины.
9. Открыть `order.html`, отправить пустую форму — проверить сообщения возле обязательных полей.
10. Заполнить форму корректными учебными данными — проверить сообщение об успешной **локальной** проверке.
11. Открыть DevTools → Console на страницах `index.html`, `catalog.html`, `product.html`, `cart.html`, `order.html` и `contacts.html` и проверить отсутствие критических ошибок.

## Ограничения учебного проекта

- Серверная часть, авторизация и платёжная система не реализованы.
- Заказ и обратная связь не отправляются по сети.
- Корзина хранится только в браузере пользователя и может быть очищена вместе с данными сайта.
- Два товара в каталоге являются учебными примерами для выполнения требований КР №4.
- Ссылка на GitHub Pages выше относится к **КР №3**; публикация КР №4 отдельно не заявлена.
